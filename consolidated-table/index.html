Create a Table Group

A Table Group defines the schema of your tables. Pick the full set of fields below, so your Detrics tables carry the campaign detail, the metrics, and the creative image every row needs. Build one Table Group for Meta and one for TikTok. The fields are named differently on each platform, so here's exactly what to tick:

Meta Ads
  • Dimensions: Date, Account Name, Campaign Name, Ad Set Name, Ad Name, Ad ID, Ad Image URL, Ad Video URL
  • Metrics: Amount Spent, Impressions, Inline Link Clicks
TikTok Ads
  • Dimensions: Stat Time Day, Advertiser Name, Campaign Name, Adgroup Name, Ad Name, Ad Id, Creative Thumbnail Url, Ad Playable Url, Creative Preview Url
  • Metrics: Spend, Impressions, Clicks, Conversion, Likes, Engagements

Time aggregation: Daily, on both. Keep the account field (Account Name on Meta, Advertiser Name on TikTok): the client mapping joins on it. The creative fields are named differently but describe the same thing, so when you consolidate you line them up into one column: Meta's Ad Image URL and TikTok's Creative Thumbnail Url both become creative_image_url.

Table Group: the dimensions + metrics above, Daily aggregation

Map each account to a client a tiny Google Sheet, read live by BigQuery

Raw ad accounts don't know who the "client" is. One client can run five accounts across three platforms. A tiny Google Sheet fixes that: you list each account and the client it belongs to, and BigQuery reads it live. Add an account or rename a client and you edit the Sheet, nothing else.

client_map

One row per real ad account, mapped to the client you report on. Column headers, exactly:

channelaccount_nameclient
Meta AdsACME_USAcme
Meta AdsACME_MXAcme
TikTok AdsAcme GlobalAcme
Meta AdsGlobex-MainGlobex
channel account_name client
client_map: each ad account mapped to a client (one client can span many accounts and channels)
★ The account_name has to match exactly what the platform reports (Account Name on Meta, Advertiser Name on TikTok). That's the key the join uses. Anything you leave unmapped still lands in the table, just with a blank client.

Let BigQuery read the Sheet

So the consolidation query can join this mapping, expose the Sheet to BigQuery as an external table. It reads the live Sheet, so every edit shows up on the next run with no export step.

  1. In the BigQuery Console, open your dataset → Create table.
  2. Source: Drive. Paste the Sheet's URL, format Google Sheets, and set the sheet range to the tab (e.g. client_map!A:C).
  3. Table name: client_map. Turn on Auto-detect schema, set Header rows to skip = 1, and Create.
✓ This client_map is your control panel. Add a client or an account in the Sheet and the next rebuild picks it up, no code to touch.

Build a creative-level report spend next to the actual ad, in Looker Studio

  

  

    
The consolidated table already carries the creative image URL for every ad. Point Looker Studio at it and you get a report where each row shows the real ad thumbnail next to its spend, filterable by client, so anyone can see which creative is eating the budget.


    
    
      
  1. Open lookerstudio.google.com → Create → Report, add a BigQuery data source, and pick your consolidated_ad_performance table.
    2. 
      
  2. Set creative_image_url's type to Image (in the data panel, click the field's type and choose URL → Image). That's what renders the thumbnail instead of raw text.
    3. 
      
  3. Drop a Table chart on the page. Dimensions: creative_image_url, client, channel, campaign_name, ad_name. Metrics: spend, impressions, clicks.
    4. 
      
  4. Add a filter control on client and sort the table by spend descending.
    5. 
    


    

      
      
Each ad's thumbnail next to its spend, impressions, and clicks, filtered to one client

    


    

      ★
      Use creative_image_url for the thumbnail, not the video or preview URL. It's populated for both Meta and TikTok and the links are permanent; the TikTok preview link expires.

Claude Code
an AI that works your computer

How we run most of growth at Detrics — not with a chatbot, with an operator that reads our real data and ships real work.

What it is

It's Claude — in your terminal.

Same model you know from the browser. The difference: it can act, not just talk.
  • Reads your files, runs your shell, calls your tools — Google, Notion, BigQuery, LinkedIn, Slack.
  • Everyone here has used ChatGPT or Claude in a browser. What's next is the entire reason we run growth on this.
The one slide that matters

Web AI vs. Claude Code

AI in the browser

A conversation in a box

It can think and write text back to you. That's the ceiling. You copy-paste the result out yourself.

→ You get a recipe.
Claude Code

Creates files. Runs programs.

The output isn't text in a chat — it's a draft sitting in your Gmail, a row in your CRM, a rendered image on disk, a query that actually executed.

→ It cooks the meal.
Why that's power

Read real data → make a real artifact → run real code to deliver it.

  • Because it can run programs, anything you can script, it can do.
  • Anything it can do once, you turn into a one-word command.
  • "The moment an AI can write a file and execute it, it stops being an assistant and becomes a teammate with hands."

Deep dive ① · a "skill"

After every demo there's 20 min of grunt work. We turned it into one word.

  • /demo-followup → .claude/commands/demo-followup.md (quick summary + rules)
  • → which points to the full SOP in growth/demos/DEMO_FOLLOWUP.md
  • → which references helper files: EMAIL_BUILDER.md, PRODUCT.md. Claude reads the recipe and the helpers, then executes.
How I built it · no code, just the recipe

The skill is a markdown file I wrote by hand.

A skill = a slash command backed by a plain‑text recipe. I never wrote a program — I wrote down how the job works, and Claude follows it.

  • I type /demo-followup
  • Claude reads the command file → summary + hard rules
  • It opens the full SOP (DEMO_FOLLOWUP.md)
  • It pulls in the helper files it needs →

The "we actually thought about this" part

The guardrails are written into the recipe.

  • Drafts, never sends. No email sent, no CRM card created, without me.
  • Source-of-truth discipline. Links come from PRODUCT.md, not memory.
  • Duplicate checks. Searches the CRM first; stops if the contact exists.
  • It writes its own rules back. I correct it once → the rule goes into the .md → it's permanent.
  • Every guardrail came from a mistake it made once. We don't retrain a model — we edit a text file.

Image generation

It knows when not to use the AI image generator.

No logos · illustration

nano banana (Gemini)

Abstract / conceptual art → generated with gemini-image.js.

Real brand logos

HTML → PNG render

Detrics, Meta, BigQuery… Gemini hallucinates logos, so it builds an HTML template and renders a pixel-perfect PNG via render.js.

That decision tree lives in CREATIVE_GUIDE.md — learned from a real failure where Gemini drew a fake BigQuery logo.

Why it looks on-brand, not generic-AI

creatives/ holds the brand system.

  • Exact hex colors (#2563EB primary blue), Inter as the font, GCS URLs for every real platform logo.
  • So when it builds an image, it pulls the real logos and real brand colors — the creative looks like Detrics made it.
  • Same pattern as the CRM skill: a capability + written-down judgment = output we'd actually ship.
